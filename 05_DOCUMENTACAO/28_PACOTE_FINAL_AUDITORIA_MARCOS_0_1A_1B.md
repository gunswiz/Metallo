**Resultado: situação A obtida**, por bind real de loopback. As sondas também incluíram os endereços IPv6 globais presentes na interface Ethernet; os resultados e motivos de falha estão no JSON. Não houve segunda máquina física da LAN, teste pela Internet, teste do endereço especial `host.docker.internal` ou ensaio de invasor com acesso administrativo ao Docker. A rede separada é outro namespace Docker no mesmo computador, não um host físico independente. A conclusão A se apoia conjuntamente nos bindings efetivos do Docker, listeners do Windows e sondas, não apenas em firewall. Loopback não é fronteira contra processos locais com acesso privilegiado ao Docker.

### Alterações efetivamente realizadas

1. Com autorização adicional explícita do responsável para o alcance global, o Docker Desktop 4.92.0 foi parado sem containers ativos. A configuração anterior foi copiada para `auditoria-final/docker-settings-antes.json`.
2. A opção oficial **Port binding behavior → Localhost only** foi aplicada no arquivo documentado `%APPDATA%/Docker/settings-store.json`, propriedade `PortBindingBehavior=local-only-port-binding`. O Docker foi reiniciado e a persistência/bind efetivo foram verificados. `docker-settings-depois.json` registra o único ajuste de configuração.
3. O iniciador passou a exigir essa restrição **antes** de iniciar containers, validar contexto Docker local e encerrar a pilha se detectar bind/listener fora de loopback ou porta esperada ausente. A antiga aceitação de wildcard baseada somente na existência de firewall foi removida. `guarda-inicio.txt` comprova o bloqueio antes da configuração.
4. `verificar-rede-local.mjs` executa as sondas. Cria rede e containers sintéticos sem volumes e sem portas publicadas, incluindo um servidor de controle acessível somente nessa rede. Remove os recursos de teste ao terminar.
5. O ensaio foi repetido após servir as Edge Functions. A pilha Supabase foi parada preservando os volumes. A opção Localhost only permanece ativa.

Não foram alterados firewall, Defender, roteador, WSL, rede física, arquivos internos gerados pela CLI ou configuração remota. A configuração global afeta publicação de portas de novos containers de outros projetos: eles também ficam locais. Para reverter, parar a pilha e selecionar a opção anterior no Docker Desktop; o iniciador bloqueará futuras partidas até que Localhost only seja restabelecido. A cópia anterior foi preservada para comparação; não restaurar indiscriminadamente um arquivo antigo sobre outras configurações futuras.

**Método reproduzível:** configurar a opção oficial e executar `validar-isolamento.ps1`.
